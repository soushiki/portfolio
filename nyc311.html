Step 1 of 6

Apps built on public data break without warning when the source changes how it answers.

The API is the line apps call to ask for 311 data. If one day it answers differently, say without a box it always sent, the app breaks.

Show the evidence

The test plan sets what is tested and what is not.

  • In scope: availability, response shape (contract), query parameters and error responses for invalid requests.
  • Out of scope: load testing, authentication, other formats, other datasets and whether the 311 data itself is correct.

# negative
def test_malformed_where_returns_compiler_error(api):
    body = assert_error_json(api({"$where": "bogus((", "$limit": 1}))
    assert body["code"] == "query.compiler.malformed"
    assert body["error"] is True

# offline
def test_schema_rejects_record_missing_required_field(fixture_records, schema, field):
    bad = copy.deepcopy(fixture_records[0])
    del bad[field]
    with pytest.raises(jsonschema.ValidationError):
        jsonschema.validate(bad, schema)

Schema excerpt: the required boxes

"required": [
  "unique_key", "created_date", "agency", "agency_name",
  "complaint_type", "status", "borough"
]

Error codes the negative tests pin

  • 400 with code = query.compiler.malformed: broken $where, invalid $limit or $offset
  • 400 with errorCode = query.soql.no-such-column: a column that does not exist in $select or $order
  • 400 with errorCode = query.soql.type-mismatch: text compared to a date
  • 400 with "Unrecognized arguments": an unknown query parameter
  • 404 with code = dataset.missing: a dataset that does not exist

Step 5 of 6

The data changes daily, so the tests check rules, not exact values.

  • Problem

    The data changes every day, so exact values cannot be fixed.

    Decision

    Tests check properties (filters, order, types). Date tests use a day that is already closed, 2023-01-01.

  • Problem

    A network or server outage would fail tests that are not product bugs.

    Decision

    One retry, only for 429 and 5xx. 4xx are never retried, because the negative tests expect them. A red run caused by an outage is re-run before anything is reported.

  • Problem

    Error messages are undocumented and their shape can change.

    Decision

    Checks come from responses observed live and are pinned; if the shape changes, a test fails. There are two error shapes, one with code and one with errorCode.
